# Generate the docs/core.md props reference from the types

docs/core.md is the linked "full API reference" (packages/core README) and is
actively maintained for the GPU surface, but the older sections still carry
stale fragments and the props coverage is hand-copied - the exact mechanism
that produced the wrong-props era the core package review documented
(`fill`, `background`, `imageWidth`). Two of those fragments survive today:
the `<view background="#eee">` example and an `imageWidth`/`imageHeight`
comment in the createTexture example. Coverage gaps: env/capabilities
detail, events (pointer/key/text contracts are documented only in types),
gamepads, gradients, `pct`, scroll, portal, text-input mechanisms, the
subpath modules, and `ref` (on every element, documented nowhere).

## The idea

The enumerable surface should be generated, not written:

- `packages/core/jsx-runtime.d.ts` is a plain table: 15 intrinsics, each a
  flat intersection of named interfaces (`rect: RectProps & LayoutProps`,
  `"d-rect": RectProps & GeometryProps`, ...). No generics, no mapped
  types. It IS the authority on which element takes which props - the
  review's mismatch class (an intrinsic listed that does not exist, an
  exported props type with no intrinsic) is instantly visible in it.
- `packages/core/src/types.d.ts` (~590 hand-written lines) holds the
  interfaces with doc comments already following the divergence-only
  policy - exactly the right density for a generated reference: every prop
  with its exact type, prose only where semantics deviate from CSS/DOM.

Generator: walk the intrinsics table, resolve each intersection, emit
per-element prop tables (name, type, doc comment) plus one table per shared
bucket (Layout/Paint/Transform/Pointer) that elements reference instead of
repeating. Output lands in a marked `<!-- generated -->` block inside
docs/core.md so the README keeps linking one page; committed, regenerated by
running the script.

Hand-written prose stays hand-written: concepts, contracts, the GPU
sections, window/boundary shaders. Generation cannot write semantics, and
that content is current and good. The imperative surface (onFrame,
measureText, the GPU calls) also stays hand-maintained - its contracts are
prose-heavy and flux-types parity already guards it.

## Wrinkles found while scoping (2026-08-06)

- **Toolchain**: the repo pins `typescript@^7` - the native tsgo wrapper,
  CLI only, no JS compiler API (`node_modules/typescript/lib` has just
  tsc.js). TS 5.9.3 sits in the bun store as a transitive dep WITH the full
  API (`node_modules/.bun/typescript@5.9.3/.../lib/typescript.js`). The
  script (run with `bun`, never npm/npx) can resolve it from the store with
  a clear error if it disappears, or a `typescript@5` dev-dep alias gets
  added. Start with store resolution: zero new dependencies.
- **Comment-style prep**: several prop groups in types.d.ts use `//` line
  comments instead of `/** */` JSDoc (TransformProps, TextureProps.params,
  RectProps.radius, LineProps preamble, ...). Line comments are invisible
  to IDE hover and awkward trivia for a generator. Converting them is a
  mechanical prep edit with an independent payoff (hover docs) and does not
  violate the divergence-only policy - same content, visible form.

## Stages

1. Comment-style prep in types.d.ts; `scripts/` generator (bun + TS
   compiler API); marked generated block in docs/core.md; commit the
   output. Alongside: the hand-prose fixes (the two stale fragments above)
   and the missing hand-written sections.
2. Optional: CI drift gate that regenerates and diffs, like the examples
   types gate.

Related: the core package review (okf/notes/core-package-review.md)
carries this as improvement point 1; its AGENTS.md-drift point 4 is
adjacent but separate (AGENTS.md is prose by design and stays
hand-written).
