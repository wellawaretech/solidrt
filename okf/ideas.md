# Ideas

One line each. No frontmatter, no ceremony. A shaped idea graduates to a file
in `backlog/` and its line goes: this file holds open ideas only, so it stays
small.

Substance is the bar: an idea here needs a decision, a design or an
investigation before anyone could start. Work where the fix is already obvious
is not an idea, it goes in [tiny.md](tiny.md).

- Evaluate `changesets` for release management: version bumps, changelogs and dist-tag selection across `@solidrt/*`, replacing the hand-rolled bash in release.yml. Only worth it once release cadence picks up or version drift hurts.
- `instances` on an isolate handle: N instances of one module behind one handle, calls spread over them; shape undecided, a pool is userland today (N `isolate()` calls). Left open when okf/done/isolate-follow-ups.md closed.
- Error containment visibility: a native diagnostic flag on a node whose prop or child expression is contained (kept its last value after a throw), so /tree and the inspector show it, plus a dev-only outline. Only if the `Contained error` log line proves insufficient (okf/plans/reactivity-halt-containment.md).
- Focus under `display: "none"`: browsers blur a focused element when an ancestor hides; today a TextInput in a hidden pane keeps focus and keeps receiving keys. Decide whether hiding blurs (and whether re-showing restores), then wire it in the focus session. Left open when okf/done/display-none-subtree.md closed.
- Slow rebuild frames on the 3d demos: `the-third-dimension` logged paint 70.6 ms for 14 nodes and 85 ms for 8 nodes at startup. Suspicion: a resize frame blocking on raster-thread RPCs (`CreateDrawTarget`, `ResizeShaderTexture`) behind a queue ~10 deep at ~6 ms of GPU work per frame. Unverified. Left open when okf/done/stats-overlay-stale-phase-shares.md closed.
- `@solidrt/2d` `layer.records` growth replaces the array; a hoisted reference becomes a detached copy and writes go nowhere silently. The doc states it; a dev-mode generation check on `touch()` would make it loud. Only if it bites again.
- flux gpu creates silently ignore unknown opts keys: a typo'd option, or a new option against a stale client binary (seen live with `instanceOrder` - the probe just failed, no error), is accepted and does nothing. The guard lists in `collect_entry_half`/`collect_draw_target_spec` only reject known cross-surface keys; the dev-policy answer is a throw on any unrecognized key, which needs each create to own its full key inventory.
- Raise the GLES 3.0 floor? No compute keeps recurring as the wall: rules out GPU sorting (okf/done/gpu-instance-order.md, gaussian-splats' 3.1 probe-up) and the VFX-Graph tier of GPU particle simulation, and every surveyed engine does its top scale on compute. Deliberate discussion needed on what 3.1 (or a probe-up) buys, what hardware it drops, and what stays CPU regardless - not now, but the instances keep accruing.
- Partial repaint stage 3 extras (okf/done/partial-repaint.md): eglSwapBuffersWithDamageKHR / eglSetDamageRegionKHR so the SYSTEM compositor also recomposites only the damage rect (needs owning the swap path SDL currently does), and multiple damage rects so two distant small animations do not union into a near-window rect. Both wait for a measured victim; damagePx quantifies the union problem the day an app has it.
- `sol render --step <ms>`: decouple the app's simulation step from the capture rate. `--fps` is both today, so a clamped-dt app barely advances at low capture rates (`--duration 14 --fps 1` is fourteen clamped steps; fourteen real seconds need `--fps 30` and 420 PNGs). Sketch: the capture loop drives K lockstep sub-draws per written PNG and discards K-1 readbacks, lattice's playback timeline advances by the step, `rate` reports 1000/step. Left open when okf/done/playback-window-size-zero.md closed.
- A tap recognizer in core beside `createPan`/`createTransform`: `createPress` lives in packages/components (press.ts), so a package-level control (the 2d camera, the 3d cameras) cannot use it without inverting the layering and derives a tap by hand as "a press that never engaged the transform recognizer". One `createTap` in core, arena-aware, would give every control the same rule.
- `examples/camera.tsx` in @solidrt/2d logged a 54 ms first frame (layout 50.8 ms, 396 paraShapes, 2628 measureCalls) for a seven-node tree with two text nodes, on the pre-resize 1706x960 frame. One-off and possibly font loading, but out of proportion for that tree; measure before believing.
- 3d: a segment narrowphase for picking `lines` geometry (Three's Line.raycast threshold); lines pick by box today.
- 3d: wide lines as quad-expanded geometry (Three's Line2); GL ES lines are one pixel.
- Depth pre-pass switch on a 3d target for heavy-fragment scenes (from [[amber-quill]] item 1): a second scene draw with a depth-only override before the color pass, so every layer shades once. Godot's Forward+ has it on by default and off for tile-based mobile GPUs, which already resolve overdraw. Waits for a measured victim the front-to-back opaque sort does not fix.
- A trackball/arcball 3d control (no fixed up vector, quaternion pose; Three's TrackballControls/ArcballControls) for CAD-style inspection across the poles. Not orbit-pipeline work; its own control if anything asks.
- Object manipulation controls (Three's TransformControls gizmo and DragControls) over `scene.pick` and `unproject`; not a camera, its own item.
- Per-push frame demand for texture video: alloy's latch holds standing demand while a player plays (every vsync presents; measured the same picture as the pump on the tablet 2026-09-22), and the texture path could instead request one frame per pushed frame now that frames are latched against a deadline, halving presents for 25 fps content on the TV; the plan (okf/plans/video-texture-off-frame-loop.md, section 4) wanted it measured on the TV and it never was. Needs a switch to build and a TV session.
- The alloy unit-test binary takes over ten minutes to compile from a warm cache (`cargo test -p alloy --lib`), long enough that test runs get backgrounded and forgotten; find what makes the test profile so much heavier than the check (monomorphization in the test-only code, opt-level for tests, or the dev-dependency set) and cut it.
- The tablet's plane census ladder in okf/notes/android-video-plane-compositing.md (94% on pattern with the dev badge) did not reproduce on 2026-09-22 for either the previous commit's client or the new one (75-90%); either the device's state (thermal, background work) or the dev client changed since; worth understanding before the ladder is quoted again.
- Video plane hole timing: the window is translucent from the start, so between a plane's creation and its first latched frame (and between the last frame and teardown) uncovered pixels show an empty plane; open is whether the runtime should hold the hole closed until the first latch or an app covers it until `ready()`.
- Video plane display mode: on a display with several modes the plane could ask for one the clip's frame rate divides (`Surface.setFrameRate` from API 30, a preferred display mode below it, as on the Android 8 TV); open is which API per version and whether an app opts in. A dead end on single-mode panels like the Tab A7's (okf/notes/android-video-plane-compositing.md, the latch rule).

- sol as a packed flux app: `bin/sol` exec'ing `flux` directly and `sol pack --flux` packing sol itself, once flux has a story for finding `solidrt-go`, `bun` and the platform package; until then the extra move buys nothing (okf/done/cli-flux-migration.md, Packaging).
- Derive the Android versionCode from the package version instead of tracking a second number by hand. The obvious scheme (major*1e6+minor*1e3+patch) ignores a prerelease tag, so two prereleases get the same code, which Android treats as no update; that footgun is why okf/done/packed-apk-data-on-device.md kept the explicit key. Wanted: a derivation that never repeats a code for a different version string.
- Shared paint values: a named gradient, shadow or light that many nodes reference and one write updates, so a theme-wide change (a light moving, a palette animating) is one write instead of N per surface. The lit prototype measured p50 ~11 ms of JS per frame for 48 surfaces with the light orbiting even with interned paint (okf/design/lit-components.md). Only if a per-frame theme effect is wanted.
- `sol tool` finds tools only under `node_modules/@solidrt/*`, so a third-party extension's bake tool is never listed; candidates: the project's direct dependencies that themselves depend on `@solidrt/core` and ship `tools/` (no new marker, no transitive noise).
- `crypto.getRandomValues` and `crypto.randomUUID`: flux's `crypto` has `subtle` only, so a program has no unpredictable randomness and no standard unique id; `Math.random` is neither. Needs the entropy source chosen under the dependency rule (a forge capability over a proven crate) before the standards plugin is one screen of marshalling.
- Timers due at the same instant fire with no microtask checkpoint between them: two `setTimeout`s of one delay log "a b a-chain b-chain", since both are ready in one poll of the executor, where the web runs a checkpoint after every task; measured 2026-09-30 on the real timer path (okf/done/test-harness.md, Owed after stage 2); decide whether flux follows the web here and what it costs per timer.
- `sol run --capture` records key events only, so a recorded session cannot replay a gesture under `sol render` and a pointer interaction cannot become a playback script; pointer downs, ups and moves need a script form (with their times, now that events carry `timeStamp`) and the playback loop has to feed the resampler as the dev connection does for synthetic input.
- `createTransform`'s pinch gates (`QUIET`, `ENGAGE`, the span smoothing) are per-frame steps tuned on one 65 Hz tablet, so a 120 Hz panel halves every delta; the `pointerFrame` terminator's `timeStamp` is a real time now, so they can become px/s, which needs the constants re-derived and a pinch-versus-hold pass on a device.
- Raw samples on the move event (the web's `getCoalescedEvents()`): Android hands alloy every sample of a touch batch and the resampler collapses them to one move per frame, so far below the refresh rate the velocity window holds two or three samples and a drawing app loses the stroke between frames; open is the event shape (a list on the move, in which coordinate frames) and what the per-frame cost is when nobody reads it.
- A finger that pauses is not a late delivery: in a slow drag the resampler predicts a step and takes it back at every pause (about a pixel on the SM-T500); the samples' own times could tell a stream that went sparse from a batch that missed its frame, if a rule can be found that does not bring back the stall the bridge exists for (alloy/src/resample.rs).
- Contact pressure or size at the lift: a finger rolling off the panel once moved 28 px in its last 34 ms and flung at 1453 px/s, which positions cannot tell from a short flick; `MotionEvent` reports pressure and touch size per sample and both fall as the finger leaves, but they are Android-only and vary per device (okf/plans/event-timestamp.md).
- Mouse and stylus on Android still come through SDL's Java, stamped when the call arrives and without historical samples; they would go through `SolidRTSurface` like fingers, which means taking over SDL's mouse (relative mode, buttons) and pen (pressure, eraser) handling there, not only the times.
- What a test host does with resources a dropped engine held natively: `serve()` was checked (a server left listening ends with its test's engine, the next test binds the same port), an open database and a child process were not, and shutdown hooks do not run on a drop, as under an isolate's `terminate()` (okf/done/test-harness.md).
- The "runtime-free entry" tests (model-data, splat-data, textures, joints) prove under the `flux` binary only that no gui or `sol:` import crept in; a headless `flux:` import (`flux:fs`, `flux:image`) links fine there. Closing the gap needs the bundle's import list, which `sol test` has and a test does not.
- The rendertree's text vocabulary (`FontWeight`, `FontStyle`, `TextAlignment`) is still the `impellers` crate's enums although Impeller no longer shapes or draws text (text-own-rasterizer stage 2 step 3). Own enums in `rendertree::text` would complete the engine-independence rule for text and let `fontWeight` carry the CSS number instead of a nine-step enum (the engine already shapes any weight on the axis). Decide together with the own display list, which removes the remaining `impellers` geometry imports from the rendertree.
- The layout contract baseline (`alloy/src/tests/data/text-baseline.txt`, 107 KB) pins breaks in seven styles and word metrics in three. Decide whether a committed data file this size is the right form, or whether the test should pin a hash per style plus the first mismatching line on failure (smaller, less readable in a diff).
- Types for a project's own `flux:*` runtime modules outside that project: a scratch app in the checkout that imports `flux:physics3d` has no declarations (the demo keeps them in its `types/`), so `sol check` fails and the probe had to import the module dynamically; decide whether a runtime root (`solidrt.runtime`) ships its `.d.ts` beside its binaries and sol wires them into the typecheck, or a scratch app declares them itself.
- `@solidrt/2d` per-view sprite masks, the 3d view `layers` one dimension down (a mesh `layers` bitmask, a view admitting the intersecting ones; Three `layers`, Unity culling mask, Godot `canvas_cull_mask`): a layer's views draw every sprite today, so the relay demo's overview inset shows its cluster labels as streaks. Open: a mask on sprites or on groups only (a run is a group), and whether it filters per view in the shader (one draw, a uniform) or per view in the buffer. Additive; left open when okf/done/2d-world-space-text.md closed.
- 2d `lit()`: 2D lights for the sprite layer (Unity's Sprite-Lit, Godot's `light()` and Light2D) as the second stock material beside `unlit` - normal-mapped sprites, a light list in the layer params, shadows as a later step. The material model (okf/done/materials-one-model.md) left the name free for it.
